## 0. 这份文档怎么用

任何一张新图——不管是谁画、用 Figma 还是 SVG 还是 HTML 组件——**出厂前拿第 10 节的检查清单逐条对一遍**。前 9 节是条款与理由，第 10 节是清单，第 11 节是工程侧已知的坑。

一条元原则贯穿全篇：**容器归 CSS，内容归制图工具。** 图片/SVG 出厂一律白底直角，圆角、边框、阴影、间距全部由页面 CSS 给。这样换一次容器规格，全站同步。

## 1. 色彩

### 1.1 Token

| 名称 | 值 | 用途 |
|---|---|---|
| cream | `#F2EFE9` | 页面底、次级块、图内"LLM 介入"层 |
| ink | `#1C1B17` | 主文字、主要图形 |
| ink-muted | `#6B6862` | 次要文字、图注、连线标签 |
| terracotta | `#B85C38` | **唯一强调色** |
| 分隔线（白底） | `#E8E8E8` | `[v1.1]` 不透明版，见 1.6 |
| 分隔线（cream 底） | `#DDDAD4` | `[v1.1]` 不透明版，见 1.6 |

### 1.2 terracotta 纪律

- **每个视觉块至多一处。** 表格里只给主投行，stat 卡里只给一个数字，流程图里只给条件分支节点。
- 一页内可以出现在多个不同的块中（实测 job-decision 页 3 处：表格主投行 / `10×` / 短对比条），前提是**它们指向同一个事实**，橘色反而把它们串成一条线。
- 判断标准不是数量，是：**这一块里，橘色是不是唯一的那个焦点？**

### 1.3 扩展色板（仅插画层）

sage 绿 + 枯植物金：**只允许出现在封面插画的植物元素里，永不进入 UI、图表、表格。**
插画层可以比界面层宽——Anthropic 的蝴蝶也是彩色的——但要写成法，不能默认。

### 1.4 一个层级只用一种手段

`ink-muted` 本身已经是"次要"的**全部**表达。**不要再在它上面叠透明度。**
同理：想让一个元素更轻，改颜色**或**改字号**或**改字重，不要三样一起上。

### 1.5 图内三级层次（流程图/系统图）

| 底色 | 含义 |
|---|---|
| terracotta 10% + 1.5px terracotta 边框 | 判断 / 分支节点（全图唯一） |
| cream | LLM 介入的节点 |
| 白 | 常规节点 |

### 1.6 分隔线用预先算好的不透明色 `[v1.1]`

**改了底色的列或行，必须复查分隔线是否仍然贯通、颜色是否一致。**

半透明分隔线（如 `ink/10`）压在不同底色上会呈现不同色值——同一条线穿过白底段和 cream 底段，肉眼看是断的。处方是**改用预先算好的不透明色**：白底行 `#E8E8E8`，cream 底行 `#DDDAD4`。

配套见踩坑 #16：同一组件里不要叠两套分隔线实现（`box-shadow` + `background-image`），半透明线叠加会变深。**一处只留一套实现。**

## 2. 容器与宽度

### 2.1 白卡规格（自建组件与 SVG 通用）

- 底色 `#FFFFFF`
- 圆角 **12px**（容器自身）
- 边框 **1px `ink/10`**
- 内衬 **20px**
- 内部元素（如高亮行）圆角 **10px**——比容器小一档，视觉上才"嵌在里面"
- 分隔线：**单一粗细**（表头下不加重），两端**内收 10px**，色值按 1.6 取不透明版

### 2.2 宽度档位（四档，不要随意新增）

| 档位 | 宽度 | 用于 |
|---|---|---|
| 正文 | 672px | 段落文字 |
| 常规图 | 880px | 截图、表格、多数图表 |
| 宽图 | `min(1320px, 100vw - 48px)` | 天然宽的信息图（如流程图），保证 1:1 渲染不触碰印刷地板 |
| 全出血 | `100%` | **仅 hero，每页至多一次** |

**全出血是版面的 terracotta**——稀缺才成其为层级。每张图都撑满屏幕 = 没有一张是重点。

### 2.3 居中

**必须用显式 `margin-left` / `margin-right` 计算，禁用 `margin-inline: auto`。**
理由：元素宽于父容器时，Chrome 不平分——它把左边距钉死在 0，把全部溢出量塞进右边距。已在 Hero 上踩过（左 374 / 右 −275）。

### 2.4 渲染宽度不得超过源图宽度 `[v1.1]`

源图窄于 880 的，按原始尺寸居中显示，**禁止放大**。位图放大会糊；矢量图放大虽不糊，但会把版面里的字号推离三档体系。

实现：

```css
width: min(880px, var(--fig-native-w), 100vw - 3rem);
```

**唯一的例外见工作方法第 11 条**——同一节内的容器宽度一致，优先级高于 1:1 无缩放。实测案例：机制图天然宽 824，因下方紧跟 880 的双表组件，判定按 880 渲染（放大约 7%，12px → 约 12.8px，只会更清楚，印刷地板守得住）。

### 2.5 白卡与细边：两类东西两种待遇 `[v1.1]`

| 内容 | 容器 |
|---|---|
| **自建组件与 SVG** | 完整白卡（白底 + 圆角 12px + 1px `ink/10` + 20px 内衬） |
| **截图** | **只给圆角 12px + 1px `ink/10` 细边，不加白色内衬** |

理由：截图自带自己的底色和边界，再裱一层白衬等于给它加了一圈假边距。A/B 对照后作者选定细边版。
**两类内部各自统一**——不要有的截图裱白卡、有的不裱。

## 3. 排印

### 3.1 两条线（全站唯一的分类法）

| | 内容性质 | 字体 |
|---|---|---|
| **句子线** | 正文、图注、说明性文字——读者要"读"的 | Geist + Noto Sans SC（比例字体） |
| **标识线** | 编号、标签、技术串、日期、数据流转名——读者只"认"的 | Geist Mono |

判断方法：**它是句子吗？**（有主谓、要连读）是 → 句子线；是标识吗？（编号、名字、代码）→ 标识线。

已归位的例子：
- `001 — WORK`、`AI PRODUCT / MULTIMODAL` → 标识线，保持 mono
- `Cold emails welcome. Replies guaranteed if I can.` → 句子线，已从 mono 改为比例字体
- 图注正文 → 句子线；图注里的 `decisions_log.csv` → 标识线（inline `<code>`）

### 3.2 印刷地板（硬下限）

**图内中文 ≥ 12px，英文 ≥ 11px。**

- 这是**渲染后**的实际字号，不是设计稿字号。一张 1320px 宽的图缩进 880px 的栏，×0.67 之后 12px 变 8px——**违规**。
- 解决方式是给它更宽的容器（宽图档）或重构版式，**不是**靠 Lightbox 兜底。
- 例外：节点**内部**的等宽技术行可以 11px（有边框和底色托着）。**浮在空白里的字一律 ≥12px。**

### 3.3 图表内字号只三档

| 档 | 用途 |
|---|---|
| 16px | 节点标题 / 图内主标题 |
| 12px | 一切次要文字（副标题、连线标签、泳道名） |
| 11px | 节点内的等宽技术标识 |

超过三档就会显乱。

### 3.4 字重

- 中文自托管只有 **400 / 700** 两档，**不为半档字重增加字体文件**。
- 设计稿里若标了 500，**改设计稿去对齐现实**——设计稿是 spec，spec 不该写一句系统兑现不了的承诺。
- 英文 VF（Geist / Geist Mono 为可变字体）可用中间字重，需实测确认走的是真实字重而非回退。

### 3.5 绝不使用

Inter / 微软雅黑 / 系统默认 sans / 合成斜体（中文无真斜体，浏览器只会把方块字硬剪切变形）。

### 3.6 两张并置的对照表，共有列必须对齐 `[v1.1]`

两表并置阅读时，读者的眼睛会横向找对应关系。**共有列必须落在同一位置、同一宽度**（实测案例：TaskTable + Checklist 的 Priority 列均左置 60、cream 列均右置 350），**差异列居中**。

呈现层可以为此重排列序——**原始列序保留在数据源里**，不要为了排版去改 CSV。

## 4. 图注

### 4.1 定位：图注是文字逻辑，不是图名逻辑

- **图名**居中、属于图的内部——要写就在制图时写进图里（Figma / SVG 内）。
- **图外的小字一律是图注**：左对齐、双语、**故意写长**（左对齐若太短，视觉重心会偏坠）。

### 4.2 规格

| 属性 | 值 |
|---|---|
| 字体 | Geist + Noto Sans SC |
| 字号 | **14px** |
| 字距 | 0.01em |
| 行高 | **1.6**（Anthropic 的 1.2 是纯英文设定，中文不适用，不抄） |
| 颜色 | ink-muted |
| 对齐 | 左对齐，与图同宽 |
| 折行 | `text-wrap: pretty` |
| 斜体 | **不用** |

### 4.3 折行：balance 归标题，pretty 归段落

- `text-wrap: balance` 把每行削成等长——**标题**用它（追求块状对称）；用在图注上会让每行右边都空一截，整块显窄。
- `text-wrap: pretty` 保持每行照常填满，只在结尾处防孤词——**段落和图注**用它。

### 4.4 右缘毛边是天性，不要追

**左对齐 / 两行等长 / 右缘顶满——三样只能同时要两个。**
Anthropic 满站都是毛边右缘。真正难看的个案（末行只剩孤词、技术串被连字符拆开）用 **copy-fit**（调文案长度）治，不用代码治。

### 4.5 技术串

文件名、命令名、代码标识用 inline `<code>`：Geist Mono、字号继承、颜色继承、无背景无边框、`white-space: nowrap`（禁止从中间断行）。
连字符复合词（`command-line`、`two-stage`、`dual-mode`）是断行地雷——**改写掉，不要靠调虚词挪位置**。

补充：不可断的技术词（`Markdown`、文件名、复合词）会整词换行，在它前方留下一块空缺。治法同样是 **copy-fit**——把这个词挪到不靠近折点的位置，**不是**调 CSS。

### 4.6 内容要求

- 图注要说**为什么值得看**，不只报事实。（"切分为 113 个 segments" 是图名；"按条文层级切分、保留章节结构以支持逐条召回" 才是图注。）
- 涉及数字必须**写清口径**。已发生的实例：`3h41m` 是全链路耗时、`30s` 是单次判断——不写清，细心读者会算出 221÷108≈2min 然后怀疑数字造假。
- 不发明术语。图注里的说法必须与正文一致（如"判断前必过知识库""先观察、后判断分离"）。

## 5. 数据纪律

1. **估算不进图表。** 只有实测数字能进。"算上一些冗余凑个整数"——不行。
2. **每个数字都要能追溯到来源**（台账、时间戳、脚本、截图）。宁可是 `3h41m` 这种不整的数，也不要 `1h30min` 这种一看就是凑的。
3. **口径矛盾必须在图注里说清**，不能指望读者不算。
4. **匿名化一致性**：一处打码，处处打码。表格里匿了平台名，截图文件名里就不能留着。
5. AI 生成的图里若含数字/字段名，**逐一审计**，编的一律删。
6. **图表中的每一条内容都必须能追溯到数据源。** `[v1.1]`
   不只是数字——条目、任务名、字段名同样适用。若正文与数据源不一致（如 MDX 里存在数据源中没有的条目），**先报告，由作者决定删或补**，不许工程侧自行取舍。

## 6. 图的分诊与交互

### 6.1 分诊：这张图要不要重做？

| 类型 | 判据 | 处理 |
|---|---|---|
| **证据型截图** | CLI 原始输出、真实 Test Run、GitHub 页面、生成效果图 | **保留原样**（除隐私打码外不修图） |
| **信息困在截图型** | 表格、流程图全景、被压缩到读不清的界面 | **重做**为 HTML / SVG |
| **代码截图** `[v1.1]` | 任何以位图形式呈现的代码 | **一律重做为真代码块**，见 6.4 |
| **氛围图** | hero 封面、纯意象 | 不承载信息，见 6.2 |

判据一句话：**代码、表格这类"本来就是结构化文本"的，重做；"过程留痕"这类整理了就失真的，保留。**

### 6.2 交互：滚动展开 vs Lightbox，互斥

| | 含义 | 挂什么 |
|---|---|---|
| **氛围图**（hero） | "这是气质，随你滚动呼吸" | 滚动展开，**不挂 Lightbox** |
| **信息图**（截图 / SVG） | "这里有细节值得点开看清" | 静态，**挂 Lightbox** |
| **HTML 组件**（表格 / 图表） `[v1.1]` | 本身就是真文字、会响应式重排 | **不挂 Lightbox** |

**同一张图不同时挂两者**——那等于对读者说"这既是要细看的信息、又是不用细看的氛围"，交互语言自相矛盾，且点击会打断滚动动效。

**Lightbox 只给图片。** 自建组件放大没有意义：它的字本来就是可选中、可搜索、随屏幕重排的，点开只是把同样的字换个背景再显示一遍。

### 6.3 hero 封面（氛围图）判断尺子

不是"遮住标题能不能看懂"——读者永远看得到标题，图不必自我解释。正确的三问：

1. 遮住标题，**气质**对不对？
2. 配上标题，图有没有给标题**加分**？
3. 它和其他几张 hero 是不是**一家人**？

### 6.4 深色代码块规格 `[v1.1]`

代码截图一律重做为真代码块——**可选中、可搜索、永远锐利**，且不吃缩放损耗。

| 属性 | 值 |
|---|---|
| 底色 | `#1C1B17`（ink） |
| 正文 | `#F2EFE9`（cream） |
| 注释 | `#6B6862`（ink-muted） |
| 圆角 | 12px |
| 边框 | 无 |

**不引入语法高亮库。** 任何一套主题都会带进 5–8 种颜色，当场违反色彩纪律。代码的可读性靠等宽字体和缩进已经足够。

## 7. 流程图专项

- **结构是 flow，不是 concept map**：有明确的输入→分支→输出方向。
- **连线**：`ink/30`，直角折线 + 8px 圆角（曲率呼应正交，不改变正交性）。
- **连线上标数据流转名**（`context` / `desc` / `verdict`），12px mono，居中于线段。
- **泳道标签居中于线段**，不贴起点（短线段上贴左会显参差）。
- **节点内容**：中文职责在上（16px），说明在中（12px），等宽技术标识在下（11px）。
- **注释层**（失败复盘等）走 `ink/30` 虚线引出，**不占用重点色**——它是补充，不是焦点。
- 白底直角出厂，圆角边框由 CSS 给。
- **实装必须用 inline SVG**——`<img>` 引入的 SVG 是独立文档，够不着站内自托管字体（见踩坑 #7、#8）。

## 8. 间距

| Token | 桌面 | 移动 | 用途 |
|---|---|---|---|
| `--figure-gap-block` | 96px | 64px | 图块与上下正文之间 |
| `--figure-gap-caption` | 16px | 16px | 图与其图注之间 |
| 图组内多卡间距 | 16px | 16px | 同一 figure 内多张卡之间 |

### 图不挨图

两张图直接相邻会让密度感互相传染。两种解法：
1. 中间垫一段正文（首选，也是"图文交错"的本义）；
2. 若两张图是同一个论证的两面，**合为一个 `<figure>`，共用一条图注**（如 stat 卡 + 对比条）。

## 9. 移动端

1. **表格 → 堆叠卡片**，且层级要按"**相对页面背景**"重新判定。
   页面底是 cream 时：最轻的一档用 cream（融入背景）、次重用**白**（cream 上白色才是凸起）、最重用 terracotta。
   **不要把桌面的绝对色值直接搬过来**——桌面白卡上米色凸，手机米页上白色凸，逻辑是镜像的。
2. **全出血时去圆角**——圆角落在物理屏幕边缘上像渲染故障，不像设计意图。
3. **宽图在小屏依赖 Lightbox**，Lightbox 内需支持双指缩放（勿禁用 `user-scalable`）。
4. **比例可以换，但裁掉的只能是留白**。例：hero 桌面 2.35:1、移动 16:9——移动端裁掉的正好是桌面版两侧补的 cream，零内容损失。

## 10. 出厂检查清单

新图上线前逐条打勾：

**色彩**
- [ ] terracotta 在这一块里是否唯一？
- [ ] 有没有 sage / 其他颜色溜进 UI 或图表？
- [ ] ink-muted 上有没有多叠一层透明度？
- [ ] `[v1.1]` 分隔线用的是不透明色？跨底色处仍然贯通、同色？
- [ ] `[v1.1]` 同一组件里只有一套分隔线实现？

**容器**
- [ ] 白底直角出厂，圆角边框交给 CSS？
- [ ] 容器 12px / 内部元素 10px / 分隔线内收 10px？
- [ ] 宽度落在四档之一？全出血是否只有 hero？
- [ ] 居中用的是显式 margin，不是 `margin-inline: auto`？
- [ ] `[v1.1]` 渲染宽度没有超过源图宽度？（例外：同节内需与相邻组件对齐）
- [ ] `[v1.1]` 自建组件/SVG 走白卡、截图走细边，没有混用？

**排印**
- [ ] 句子穿比例字体、标识穿 mono？
- [ ] **渲染后**中文 ≥12px、英文 ≥11px（浮空文字无例外）？

## 11. 踩坑档案（工程侧）

这些坑都是实测撞到并定位过根因的，重复踩会浪费整天。

| # | 坑 | 根因 / 处方 |
|---|---|---|
| 1 | `animation-timeline: view()` 追错对象 | `body { overflow-x: hidden }` 被 CSS 规范强制把 `overflow-y` 变为 `auto`，body 成了滚动容器。改用 `overflow-x: clip` |
| 2 | 元素宽于父容器时不居中 | Chrome 对 `margin-inline: auto` 不平分。改显式 `margin-left/right: calc(...)` |
| 3 | 放大需要预留一块空白 | `transform: scale` 不改变布局盒子。改**布局宽度动画**，页面会自然回流把下方内容推开 |
| 4 | 滚动动画生硬、无惯性 | CSS `view()` 严格绑定滚动位置、零惯性。要 scrub 感须用 rAF + 指数平滑（`cur += (eased - cur) * 0.08`） |
| 5 | 动画终点算错、上下不对称 | 终点必须用**末态几何**（放大后的高度、margin 归零后的位置）计算，不能用初始几何 |
| 6 | 刷新后 LOGO / hero 位置错乱 | 标题字体从兜底 Times 换成 Instrument Serif 时页头高度跳约 84px。**任何依赖布局几何的一次性判定，必须等 `document.fonts.ready` 之后才计算**，且重算后要重置相关状态 |
| 7 | 内联 SVG 里的 mono 字体不生效 | `next/font/local` 注册的是哈希名（`__geistMono_xxx`），只通过 CSS 变量暴露，字面量 `"Geist Mono"` 匹配不上。需额外写一条字面量别名 `@font-face` 指向同一文件（同 URL，不增加请求） |
| 8 | `<img>` 引入的 SVG 用不上站内字体 | `<img>` 加载的 SVG 是独立文档，够不着宿主页面的 `@font-face`。需**内联** SVG |
| 9 | `::selection` 整条失效 | `::selection` 与 `::-moz-selection` **不能写在同一条逗号选择器里**，Chrome 认不出后者会丢弃整条规则。拆成两条 |
| 10 | MDX 里图注被正文样式接管 | 图注写成 JSX children 会被 remark 自动包一层 `<p>`，被 `.prose-works p` 的正文样式命中。**用字符串 prop 传入**，不用 children |
| 11 | 每页图片停驻位置不同 | 滚轮落点按步长量子化，而各页因页头高度不同、锚点位置各异。**统一页头最小高度**可让全站行为一致 |
| 12 | 大步长滚动跳过中间动画态 | 中间态若只靠滚动位置驱动，一步跨过窗口就永不渲染。改为**阶段状态机 + 最小停留时长**，键盘 PageDown / 锚点跳转同受益 |
| 13 `[v1.1]` | Tailwind 类名用模板字符串拼接会静默失效 | 静态扫描器看不到动态拼出的 class 名，构建时那条样式压根不会被生成。**必须写成字面量静态字符串** |
| 14 `[v1.1]` | Notion 导出的 `.csv` 可能实际是 Excel 二进制（zip） | 后缀骗人。读前先验格式；用 `openpyxl` 转成真正的纯文本 CSV |
| 15 `[v1.1]` | `subset-fonts.mjs` 只扫 `content/` `app/` 下的 `.mdx/.tsx/.ts` | **数据文件（CSV）里的中文从未进过字体子集**。已把 `design-refs/*.csv` 纳入扫描；**任何新增数据源都要确认在扫描范围内** |
| 16 `[v1.1]` | 同一组件里叠了两套分隔线实现（`box-shadow` + `background-image`） | 半透明线叠加会变深，肉眼像"有的行线粗有的细"。一处只留一套实现 |
| 17 `[v1.1]` | CSV 的 Windows 换行 `\r` 残留 | `split('\n')` 后末列名带 `\r`，匹配失败导致整列空白。读取时统一处理 |

## 12. 工作方法（元规范）

1. **先取证，后动刀。** 感觉"慢/怪/挤"，先用 DevTools、像素测量、脚本统计拿到数字，再写 brief。没有数字不动手。
2. **一次一个决策，一次只动一个数。** 同时改两个变量，出了问题分不清是谁的。
3. **每份 brief 自带可量化验收指标**，要求前后对照。
4. **视觉判断终审权归作者。** 数值是初值不是圣旨——"还空就 48，觉得挤了就 64"。
5. **设计稿是 spec，spec 不该写系统兑现不了的承诺。** 冲突时改设计稿去对齐现实（如表头 500 → 400）。
6. **回退时区分"实验功能"与"顺手捡到的正交修复"**，后者要在回退 brief 里点名保留。（吸附功能回退时误伤了字体竞态修复，导致该 bug 复活。）
7. **病因描述里的数值写错 ≠ 修法错。** 判断要不要返工，看这个数**有没有进代码**。
8. **参照系也有做不到的事。** Anthropic 的图也不保证每次滚动都精确居中——追一个原版都没做到的目标，是在浪费工程预算。
9. **顾问转录的数据一律标注"可能有误，以实际数据源为准"。** `[v1.1]`
   给 Claude Code 的 brief 里，凡是由顾问从对话中转录的数字、条目、文件名，都必须带这句标注，并**要求它核对后报告差异，不许照抄 brief**。顾问看不到本地代码与数据源，转录必然有损耗。
10. **图表类型分流。** `[v1.1]`
    **数据图**（stat 卡 / 对比条 / 表格）走 Figma 比稿 → 换算规格 → HTML 组件；**结构图**（流程 / 机制）直接出 SVG。后者更快、无转译损耗、不吃 Figma 额度、字体不出事。
11. **同一节内的容器宽度必须一致，优先于 1:1 无缩放。** `[v1.1]`
    读者在一节之内连续下滑时，容器宽度跳变比 7% 的缩放更刺眼。实测：机制图天然宽 824，因下方紧跟 880 的双表，按 880 渲染。
12. **不可断的技术词会整词换行，在其前方留下空缺。** `[v1.1]`
    治法是 copy-fit 把它挪到不在折点附近的位置，**不是**调 CSS。
