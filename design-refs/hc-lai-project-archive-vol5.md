## ① 背景与目标

Vol.4 结尾把三件"锦上添花"里的最后一件留给了未来：**截图重做成卡片/图表**。本卷就是这场工程。

起点问题：站点内容已全部上线，但作品详情页存在两个结构性缺陷——

1. **信息困在截图里**：台账表格、工作流全景等图，本质是结构化信息，却以位图形式呈现，缩到 880px 栏宽后文字不可读；
2. **图文节奏失衡**：作者原话——"要么全是文字连在一起一大片，要么两张图紧挨在一起"。

工程目标：让每一页都有能自己说话的图，且这些图不是随手画的，而是**有规范、有踩坑档案、有出厂检查清单的一套视觉语言**。

实际推进中战线自然延伸，最终覆盖：表格 HTML 化 → 版面呼吸（图注排印与间距）→ 五张 Hero 封面从生成到滚动实装 → 图表语言规范文档化 → 全站图况盘点 → 图文交错 → 补图工程（四张新 SVG + 两张表格组件）。

**贯穿本卷的分诊框架（第一刀）**：

| 类型 | 判据 | 处理 |
|---|---|---|
| **证据型截图** | CLI 原始输出、真实 Test Run、GitHub 页面、生成效果图 | **保留原样**（除隐私打码外不修图） |
| **信息困在截图型** | 表格、流程图全景、被压缩到读不清的界面 | **重做**为 HTML / SVG |
| **氛围图** | hero 封面、纯意象 | 不承载信息，另立交互规则 |

判据一句话：**代码/表格这类"本来就是结构化文本"的，重做；"过程留痕"这类整理了就失真的，保留。**

### 战役 2 · 累计耗时统计（估算不进图表）

作者一度想写"1h30min"（108 × 30s ≈ 54 分钟，"算上一些冗余"凑整）。**被拦下**——理由：这是推算 + 估计的合成数，一旦被追问"怎么统计的"，只能答"我估的"，整张图跟着贬值。

**真数字就在台账里**：`decisions_log.csv` 每条记录带时间戳。脚本 `compute_sessions.py` 读文件（带 UTF-8 BOM，已处理），排除测试行"光年之外"，按时间戳排序、间隔 >15 分钟切新时段：

| 时段 | 起 | 止 | 记录数 | 时长 |
|---|---|---|---|---|
| 1 | 05-02 19:16 | 19:16 | 1 | 0 分钟 |
| 2 | 05-03 13:21 | 13:46 | 11 | 25 分钟 |
| 3 | 05-04 13:31 | 15:38 | 64 | 127 分钟 |
| 4 | 05-04 15:57 | 16:01 | 2 | 4 分钟 |
| 5 | 05-05 13:45 | 13:55 | 5 | 10 分钟 |
| 6 | 05-05 14:12 | 14:59 | 21 | 47 分钟 |
| 7 | 05-05 15:28 | 15:36 | 4 | 8 分钟 |

**累计 221 分钟 = 3 小时 41 分。**

Claude Code 如实标注两处未圆的地方：时段 1 只有 1 条记录、首尾差为 0 分钟，没有替它编非零数字；CSV 里"光年之外"出现两次（第 1 行测试用已排除，第 113 行在 108 条统计范围之外）。

**口径纪律**：3h41m 是**全链路**（贴 JD、等解析、读卡、归档全含），30s 是**单次判断**。221 ÷ 108 ≈ 2 分钟与 30 秒的表面矛盾，必须在图注里写清，否则细心读者会怀疑数字造假。

### 战役 3 · 版面呼吸 pass

**起因**：作者对比 Anthropic 后感到"紧凑"。目测量化后归因为三处——图注用等宽字体且字号偏小、图块与正文垂直间距不足、存在图与图直接相邻。

**① 图注排印改造（全站组件，一处改全站）**

| 属性 | 原 | 新 |
|---|---|---|
| 字体 | Geist Mono | **Geist + Noto Sans SC**（比例字体） |
| 字号 | 13px | **14px** |
| 字距 | 0.05em | 0.01em |
| 行高 | 1.6 | **1.6 不变** |

诊断关键：作者形容图注"像是从 CLI 命令行里走出来的"——**因为它字面意义上就是**。等宽字体的机械感是本性（fixed-pitch 节奏 + 刻意理性的骨架），不是 bug。而站内早已立法"mono 只给技术标识"，图注是最后一个未执行这条法律的地方。

Anthropic 图注实测规格（作者用 DevTools 取证）：14px / 行高 16.8px（1.2）/ italic / 字距 0.15px / anthropicSans。**学 14px 与字距，不学 1.2 行高**（纯英文设定，中文在 1.2 会挤成一团，中文图注维持 1.6），**不学 italic**（中文无真斜体，浏览器只会把方块字硬剪切变形）。

**② 折行策略：balance → pretty（本卷最重要的排印教训）**

初版用 `text-wrap: balance`，把两行削成等长——治好了孤词，却让**每行右边都空出一截**，整块文字视觉变窄。作者形容"缺了一大块"。

诊断：`balance` 追求块状对称，是**标题**的药；图注是**段落**，该用 `text-wrap: pretty`——保持每行照常填满，只在结尾防孤词。

**入规范：balance 归标题，pretty 归段落。**

pretty 上岗后实测首行占比 95%–100%（原 55%–65%）。

**③ 右缘毛边是天性，不要追**

作者一度要求图注右缘顶满。物理规律：**左对齐 / 两行等长 / 右缘顶满，三样只能同时要两个。** Anthropic 满站都是毛边右缘。真正难看的个案（末行孤词、技术串被连字符拆开）用 **copy-fit（调文案长度）**治，不用代码治。

**④ 间距 token（新增，收在 `globals.css` 的 `.prose-works figure`）**
- `--figure-gap-block`：桌面 96px / 移动 64px（原固定 40px）
- `--figure-gap-caption`：16px

**⑤ 图注内技术串**：文件名 / 命令名用行内 `<code>`，Geist Mono、字号继承、无背景无边框、`white-space: nowrap`（禁止从中间断行）。

**⑥ 图挨图 7 处清单**（由 `.prose-works figure + figure` 自动加大间距，文案补写另计）：
1. job-decision：决策卡截图 → DecisionTable
2. nanobanana：round2-anchor → case-04a
3. nanobanana：case-04a → case-04b
4. fire-code-rag：coze-correct → dify-hallucination
5. fire-code-rag：dify-hallucination → dify-fixed
6. fire-code-rag：langchain-repo → langchain-code
7. fire-code-rag：langchain-code → langchain-test

**⑦ contact 脚注归位**：`Cold emails welcome. Replies guaranteed if I can.` 原为 mono 10px，实为完整句子，按"句子线"归位为比例字体 14px。

**⑧ ::selection 陶土淡染**：学 Anthropic 用自家色而非浏览器默认深蓝。初值 `rgba(184,92,56,0.22)`，作者觉得偏淡，加深至 **0.35**，提为 `--selection-bg` 变量。（可读性从不是约束：α=0.45 时与 ink 文字对比度仍有 8.7:1，远超 4.5:1 要求，纯粹是浓淡口味。）

### 战役 5 · 系统流程图 v5（visual-standard · Dify 双模式工作流）

**从 v1 迭代到 v5 定稿**，天然宽 1320 × 530。

**结构**：flow 而非 concept map——用户输入 → 条件分支（唯一 terracotta）→ IF 无图路径（知识检索 text → 文字回答 → 输出1）/ ELSE 有图路径（视觉分析 → 知识检索 text+vision → 图片判断 → 输出2）。

**规范条款（由这张图立法）**：
- 白底直角出厂，圆角/边框由 CSS 给；
- 节点圆角矩形，连线 `ink/30` 直角折线 + 8px 圆角（**曲率呼应正交，不改变正交性**）；
- LLM 节点铺 cream（橘=判断 / 米=模型介入 / 白=常规，三级层次）；
- 连线上标数据流转名（`context` / `desc` / `verdict`），居中于线段；
- 泳道标签**居中于线段**，不贴起点（短线段上贴左会显参差）；
- 失败复盘走 `ink/30` 虚线引出**注释层**，不占重点色；
- 字号三档：标题 16 / 次要 12 / 节点内等宽 11；
- **浮空灰字不叠透明度**——ink-muted 已是"次要"的全部表达。

**实装（新增"宽图"档）**：1320 塞进 880 栏 = ×0.67，印刷地板"中文 12px"当场变 8px。故新增第三档宽度：`--figure-width-wide: min(1320px, 100vw - 48px)`。这**不违反全出血纪律**（全出血指撑满 100vw、每页至多一次、只给 hero），两侧仍留 cream。

**居中必须用显式 margin 计算**，禁用 `margin-inline: auto`（见踩坑 #2）。

**挂 Lightbox**（信息型图，与 hero 相反）。

**字体两连坑**（见踩坑 #7、#8）：先是 `<img>` 引入的 SVG 够不着站内 `@font-face`，改 inline；再发现 `next/font/local` 注册的是哈希名 `__geistMono_c3aa02`，字面量 `"Geist Mono"` 永远匹配不上，需另写一条字面量别名 `@font-face` 指向同一文件（同 URL，新增请求 0、新增字节 0）。

### 战役 6 · 五张 Hero 封面

**体裁定案**：AI 首批生成出两个体裁——封面 1、2 是**诗意意象拼贴**（一个意象当主角，克制留白），封面 3、4、5 是**信息海报**（整个案例的流程数据全铺上）。否决信息海报，向诗意拼贴收敛。

理由三条：信息海报放页首等于把正文剧透一遍；手机上海报里的小字全变蚂蚁（csv-log 的病第三次投胎）；"一个意象 + 呼吸感"正是最初被 Fable 5 打动的东西。

**判断尺子（本卷最重要的方法论修正）**

作者最初的尺子是"遮住标题能不能看懂"。**这把尺子本身是错的**——读者永远看得到标题；Fable 5 的蝴蝶单拎出来也没人猜得到是"新模型发布"。图的任务不是自我解释，是**定调**。

正确的三问：
1. 遮住标题，**气质**对不对？
2. 配上标题，图有没有给标题**加分**？
3. 它和其他几张是不是**一家人**？

**无字决定**：最终定为一个字都不写。分工逻辑——标题告诉读者"这是什么"，hero 让他"感受到气质"，正文告诉他"具体怎么回事"；hero 若也忙着解释，三层就有两层在干同一件事。副作用全消：PS 重排文字的苦活消失、手机蚂蚁字的死结消失、图内假数字的审计问题消失。

**提示词两段式**（风格底座 + 单图意象，底座五张共用以保证一家人）。底座关键约束：cream `#F2EFE9` 底、terracotta 小面积 accent、sage 绿仅限植物元素、纸质拼贴质感、**明令 NO text / letters / numbers**、16:9、主体居中留白。

**五张意象**：
| 案例 | 意象 |
|---|---|
| visual-standard | 放大镜压在产品主图上 + 右侧勾选框 |
| fire-code-rag | 摊开的规范册，陶土色细线牵出条文到火漆标签 |
| job-decision | 三摞招聘卡分拣，一摞盖火漆印 + 眼镜铅笔 |
| nanobanana | 同一栋建筑：白模 → 渲染，中间箭头 |
| ai-workflow | 散纸 → 牛皮夹（陶土书签）→ 码齐卡片 |

**绿色立法**：sage 绿 + 枯植物金写入规范为**封面扩展色板，只许在插画层出现，永不进 UI 与图表**。（Anthropic 的蝴蝶也是彩色的，插画层本就可以比界面层宽——但要写成法，不能默认。）

**色差不调**：作者判断"Anthropic 自身也有色差，手工纸感容许批次差异"——顾问支持：追求像素级同色会把"拼贴"追成"印刷"，丢了灵魂。

**PS 工序**：超分放大 + 箭头补实 + **横向扩画布**（3344×1882 → 4140×1882 → 5646×1882），只加两侧 cream，画面内容一个像素不动，顺手把主体挪正。

**比例演进（后期变成纯 CSS 旋钮）**

| 阶段 | 比例 | 问题 |
|---|---|---|
| 初版 | 16:9 | 满宽时图高 1071 > 可视区 953，顶部永远被裁 |
| v3.4 | 2.2:1 | 完整显示窗口仅 87px < 一格滚轮，接不住 |
| v3.5 | 3:1 | 主体从 1538 缩到 1128px，"清明上河图"感 |
| **定稿** | **2.35:1** | 主体 1440px、窗口 142px、上下 cream 各 71px |

关键认识：母版做到 3:1 且两侧全是纯 cream 后，**比例变成纯 CSS 旋钮**——容器设任何更窄比例 + `object-fit: cover`，裁掉的只有 cream，零内容损失、随时可逆。移动端单独用 16/9 + cover，正好裁掉后加的 cream，还原最初构图。

### 战役 7 · Hero 滚动放大长征（v3.2 → v3.10）

本卷最长的一场，前后十余轮。

**扒源码取证（决定性转折）**

作者提供 Anthropic DevTools 三帧数据后，顾问一度误判"它只长大 9.5%"（错因：作者 DevTools 侧边停靠，视口被压到约 1361px，而其起点 1272px 在该宽度下已占 93%）。后经浏览器连接直接查询 GSAP ScrollTrigger 实例，拿到完整配方：

```
GSAP ScrollTrigger
  trigger: .duraldar-cta_section
  start: "center 70%"   → 元素中心到视口 70% 高处开始
  end:   "center 40%"   → 元素中心到视口 40% 高处结束
  scrub: 0.8
  实测滚动区间：286px（视口 953px，约 0.3 屏）

补间 ease: power2.out
  max-width:      1272px → 100%
  margin-top/bot: 64px   → 0
  border-radius:  24px   → 0px
```

**三个机制性差异（不是参数差异）**

| # | 我们的做法 | Anthropic | 后果 |
|---|---|---|---|
| 1 | `transform: scale` | 布局宽度动画（`max-width` + `margin`） | scale 不改变布局盒子，必须**预留空白**给它长 → 标题与图之间出现空洞 |
| 2 | CSS `animation-timeline: view()` | GSAP `scrub: 0.8` | view() 严格绑定滚动位置、零惯性，easing 再调也生硬；scrub 是"目标跟随滚动、实际值用 0.8 秒缓动去追"，停手后还会滑行一小段 |
| 3 | 终点 96vw + 圆角 12px 不变 | 终点 100% + 圆角归零 | 一个真留了空，一个视觉上永远还在"卡片里" |

**最终实现（原生 JS，不引 GSAP——为一个效果背 50KB 与抠字体子集的家法冲突）**
- 放弃 CSS scroll-driven animation，改 rAF 循环；
- **预先计算**触发起止的绝对 scrollY 并缓存（resize 重算），避免"元素动画改变自身位置又被自己追踪"的自我追逐；
- 每帧：由 scrollY 求进度 p → 套 `power2.out`（`1 - (1-p)²`）→ **惯性追赶** `cur += (eased - cur) * 0.08`（≈ scrub 0.8）→ 写入 width / margin / borderRadius。

**关键修正 · 终点锚定用末态几何**

作者反馈"就差一次滚动"——"放到最大"与"上下对称"相差一格。根因：`endScrollY` 按**初始几何**计算，而放大过程中 hero 高度增加约 266px、图心下移约 133px。修正为用**末态几何**（宽 documentWidth、高 documentWidth ÷ aspect、margin 归零后的位置）计算。修正前 547.1 → 修正后 664.06，与实测对称点 663 几乎完全吻合。

**白边自适应（HERO_BAND）**

白边原是"副产品"（= (视口高 − 视口宽 ÷ 比例) ÷ 2），窗口形状一变就漂移（Windows 71px / Mac 约 30px）。改为**由白边反推比例**：

```
HERO_BAND = 71
aspect = clamp(2.0, docWidth / (innerHeight − 2 × HERO_BAND), 3.0)
```

白边从副产品变成设计常量。（曾试 HERO_BAND=90，主体瘦 5% 且"卷轴感"回归，退回 71。）

**ProjectHeader 高度对齐**

作者发现五页图片停驻位置各不相同。根因：滚轮落点按约 100px 量子化，而各页 ProjectHeader 高度不同（标题折行行数不同）导致各页 `endScrollY` 不同，余数因页而异。**修法：统一 ProjectHeader 最小高度**，五页 endScrollY 相等 → 同一设备上五页行为一致。顺带治好"不同页 LOGO 触发格数不同"。

**LOGO 卡点（彩蛋）**

滚动到位那一刻 LOGO 从 `H.C.` 变 `H.C. Lai`——原为巧合，后主动对齐：

```
THRESHOLD_LAI  = endScrollY − LOGO_LEAD_FRACTION × innerHeight   // 0.15
THRESHOLD_FACE = THRESHOLD_LAI − 100
```

演进：先让第一段对齐（居中时显示 `H.C.`），后按作者要求把对齐权交给**第二段**（居中时名字长全）。补偿量 5%vh（≈44px，小于一格滚轮，体感零变化）→ **15%vh**（≈132px ≈ 一格出头），实测精确命中"提前一格 + 同格重合"。

**已撤销：吸附（snap-to-center）**

曾实现"停止输入后自动滑到 endScrollY"，因与字体加载存在竞态而**整体回退**：`ProjectHeader` 标题在 Instrument Serif 加载完成前用 Times New Roman 兜底，两者高度差 **83.84px**（大于 HERO_BAND 71px），吸附会用错误的 endScrollY"很自信地"把用户按在错的位置，且标记"已吸附"不给第二次机会。

**并且**：回退吸附时误伤了它顺手带来的**正交修复**（等 `fonts.ready` 后重算），导致该 bug 后来复活。→ 入工作方法：**回退时区分"实验功能"与"顺手捡到的正交修复"**。

**Mac 大步长跳段**

作者 Mac 用 LinearMouse（By Lines），单次步长 150–250px，一步跨过 LOGO 两段之间的 100px 窗口，中间态从未被渲染。修法：连续路径加**阶段状态机 + 最小停留**（跨越一段以上时逐段推进，每段至少 300ms）。该修法**步长无关**，同时保护键盘 PageDown / 锚点跳转 / 浏览器恢复滚动位置等一整类跳跃场景。

（作者后将 Distance 改为 3——Windows 滚轮默认即"每格滚 3 行"，约 100px，落回可见窗口。）

**清晰度收官**
- `sizes` 从 `100vw` 改 `130vw`（因 `object-fit: cover` 在 2.35 比例下横向裁掉约 21.7%，浏览器按容器宽选档会分辨率不足）；
- `next.config` 的 `deviceSizes` 新增 **2560** 档（原 2048 → 3840 阶梯太粗，曾导致 +293% 字节）；
- hero `quality` 由默认 75 → **85**（手工纸纹是高频细节，q75 会抹平；实测 q85 多保留约 86% 细粒度纹理）；
- 实测 1920 视口 **181.1 KB**（基线 54.9 KB），低于 250KB 阈值，采用。

**未采纳的方向**：Anthropic 的丝滑还有一部分来自平滑滚动库（页面整体滚动带惯性）。属全站级改造，会改变整个网站滚动手感，**不碰**。

**认下的物理**：Anthropic 自己也没有 snap——用滚轮停下时图不保证正好居中，落在哪全看那一格的缘分。**追一个原版都没做到的目标，是在浪费工程预算。**

### 战役 15 · 正文口径校正（本卷最重要的内容层决定）

发现：ai-workflow 04 节写着"这套 workflow 在 **4 个真实场景**下做了验证……每个 case 都包含**真实的** messy input"。作者说明：input 其实是模拟的，当年在 Notion 作品集阶段为了"看着更真实更落地"这么写。

**定稿**：
> 中文：这套 workflow 在 4 类典型场景下做了结构验证，input 为模拟样本。每个 case 包含一段 messy input 与完整的 A–E 输出，验证的是 schema 能否承接不同类型的混乱输入，而不是真实项目中的产出效果。
>
> English: The workflow was structurally validated across four representative scenario types, using simulated input. Each case pairs one stretch of messy input with a full A–E output — what this tests is whether the schema holds across input types, not how it performed on a live project.

## ⑤ 我们的协作方式

### 5.1 角色分工（未变）
- **作者（赖兴菁）**：最终审美决策者、需求方、视觉把关人
- **Claude（"姐姐"）**：策略顾问 + 质量审查 + 概念解释 + 输出 ready-to-paste 的 brief；**不是主要建造者**
- **Claude Code**：工程实现（本地执行）

### 5.2 工作流
chat 讨论设计 → 顾问写 brief → 作者贴给 Claude Code → 本地 `npm run dev` 预览、截图给顾问审查 → 确认 OK → `git push` → Vercel 自动部署

### 5.3 本卷新增/强化的协作原则

1. **顾问看不到 Claude Code 的界面。** 它的所有产出都要由作者转贴。（本卷曾因作者未转贴而卡住一轮。）
2. **数字要绝对值，不要只给百分比。** "+230%" 无法判断（基线 60KB 与 180KB 结论相反），"181KB" 可以。
3. **brief 里凡是顾问转录的数据都必须标注"可能有误，以实际数据源为准"**，并要求核对后报告差异，**不许照抄 brief**。（本卷曾发生顾问把 Notion 截图当成 MDX 内容、让 Claude Code"核对"两个不同产物的事故。）
4. **一次一个决策，一次只动一个数。**
5. **每份 brief 自带可量化验收指标**，要求前后对照。
6. **视觉判断终审权归作者。** 顾问给的数值（96px 间距、HERO_BAND 71、比例 2.35）都是**初值不是圣旨**——"还空就 48，觉得挤了就 64"。
7. **不用块序编号跟作者说话。** `#18` 这类编号只在 brief 内部用，对话里说"04 节开头那段"。（本卷作者明确表示"最近几轮都不太懂在改什么"。）
8. **给 Claude Code 的"报告项"要明确标注"只报告、不处理"**，避免它替作者做主。
9. **回退 brief 里要点名保留"顺手捡到的正交修复"。**

### 5.4 Claude Code 的表现（值得延续的习惯）

本卷多次出现值得记功的工程行为，均应继续鼓励：
- **拿证据定罪**：用 CSSOM 实测 `cssRules` 为空数组证明 `::selection` 规则被丢弃；用 `document.fonts` 列出已注册字体证明字面量 `"Geist Mono"` 不存在
- **推翻顾问的错误假设**：不是全局样式漏排除，是组件自己叠了两套分隔线；cream 也没"盖住"线，是那一列压根没套分隔线样式
- **停下来问而不是编**：拒绝从其他小节东拼西凑填满表格三列，"这不是核验，是让我替你重新转录一遍"
- **不盲从错误指令**：顾问 brief 写"沿用 cwebp q90"，它查出该图从来就是 PNG、仓库里根本没有 cwebp 痕迹，按实际处理方式执行
- **主动纠正数据**：盘点说"字段规范 7 条"，它数了两遍核对行号确认是 6 条，没有替顾问补第七条
- **自曝其短**：承认自己踩了 `DecisionTable.tsx` 注释里早就警告过的 Tailwind 动态类名坑
- **诚实标注环境限制**：沙盒视口锁死、rAF 在后台标签页不触发时，明说"验证不了、麻烦你真机看"，不硬造截图

## ⑥ 经验原则库（本卷新增）

### 排印与版面
1. **balance 归标题，pretty 归段落。** balance 追求块状对称，用在段落上会让每行右边都空一截，整块变窄。
2. **左对齐 / 两行等长 / 右缘顶满，三样只能同时要两个。** 右缘毛边是左对齐排版的天性；真正难看的个案用 copy-fit 治，不用代码治。
3. **连字符复合词是断行地雷**（`command-line`、`two-stage`、`dual-mode`）——**改写掉**，不要靠调虚词挪位置，窗口宽度一变还会炸。
4. **两条线：它是句子吗？** 是 → 比例字体；是标识（编号/名字/代码）→ mono。内容性质变了，字体跟着变（如 `Claude API` 从标识扩写成一句话后，就该回到句子线）。
5. **印刷地板看渲染后，不看设计稿。** 1320 的图缩进 880 栏，12px 就变 8px。
6. **一个层级只用一种手段。** ink-muted 已是"次要"的全部表达，不要再叠透明度。
7. **文字视觉中心比基线高约 0.35 × 字号。** 框内明细垂直居中时要减掉这一刀，否则整组偏下。
8. **`·` 和文字拆成两个 text 元素**，各自固定 x，对齐才是数学的而非估算的。

### 图表与信息设计
9. **全出血是版面的 terracotta。** 每张图都撑满屏幕 = 没有一张是重点。
10. **氛围图 ≠ 信息图。** 前者滚动展开、不挂 Lightbox；后者静态、挂 Lightbox。同一张图不同时挂两者——那等于对读者说"这既是要细看的信息、又是不用细看的氛围"。
11. **Lightbox 只给图片，不给 HTML 组件。** 组件本身是真文字、会响应式重排。
12. **hero 的尺子不是"看懂"，是"看对气质"。** 读者永远看得到标题；图的任务是定调，不是解释。
13. **贯穿性的东西不进主脉。** Round/State 管理、治理原则这类"作用于全程"的层，画成侧轨或地基，不要串在流程末尾。
14. **对照图的共有列必须对齐同一位置**，差异列居中——版式本身就会把论点说出来。
15. **强调要选对轴。** 一张论证"结构"的图，不该按"紧急度"强调；若某列取值全部相同（如 6 行全 P0），强调它等于没强调。
16. **框按内容收窄，省下的宽度让给连线间隙。** 间隙宽读作"流动距离"，框内空读作"没排完"。
17. **渲染宽度不得超过源图宽度。** 放大必糊且无解。
18. **改了底色的列/行，必须复查分隔线是否仍贯通、颜色是否一致。** 半透明分隔线压在不同底色上会呈现不同色值，应改用预先算好的不透明色。

### 内容与数据
19. **估算不进图表。** 宁可是 3h41m 这种不整的数，也不要 1h30min 这种一看就是凑的。而且真数字往往就躺在留痕里。
20. **口径矛盾必须在图注里说清**，不能指望读者不算。
21. **图注不是发明名词的地方。** 措辞必须与正文一致，不另造术语。
22. **桥接句只描述输入，不剧透结论。** 反直觉的发现该留给图和结论小节去揭晓。
23. **一句软的，会让人对硬的那些也起疑。** 可核验是这个站最值钱的东西；overclaim 的风险不在被查出来，在被追问。
24. **说实话的版本往往更强**——它暴露的是"知道验证和证据是两件事"的方法论素养。
25. **匿名化一致性**：一处打码，处处打码；源文件改了要重新转档，否则线上还是旧的。

### 工程方法
26. **先取证，后动刀。** 感觉"慢/怪/挤"，先拿数字，再写 brief。
27. **参照系也有做不到的事。** Anthropic 的 hero 也不保证每次滚动都精确居中——追一个原版都没做到的目标，是在浪费工程预算。
28. **机制差异 ≠ 参数差异。** 调了十轮参数没用时，回头看是不是用错了机制（transform vs 布局动画、CSS view() vs rAF 惯性追赶）。
29. **依赖布局几何的一次性判定，必须等 `document.fonts.ready`。** 兜底字体与正式字体的高度差可达一整行（本站实测 83.84px）。
30. **回退时区分"实验功能"与"顺手捡到的正交修复"**，后者要点名保留。
31. **病因描述里的数值写错 ≠ 修法错。** 判断要不要返工，看这个数**有没有进代码**。
32. **量子化的脚踩不中连续的点。** 滚轮落点按步长量子化，而目标位置是任意实数——统一各页的锚点位置可让行为一致，但不能保证精确命中。
33. **图表类型分流**：数据图走 Figma 比稿 → 换算规格 → HTML 组件；结构图直接出 SVG（更快、无转译损耗、不吃额度、字体不出事）。
34. **同一节内的容器宽度必须一致，优先于 1:1 无缩放。**（机制图天然宽 824，因下方紧跟 880 的双表组件，按 880 渲染放大 7%，避免同节内容器宽度跳变。）
35. **不可断的技术词（Markdown、文件名、复合词）会整词换行，在其前方留下空缺。** 治法是 copy-fit 把它挪到不在折点附近的位置，不是调 CSS。

## ⑦ 踩坑档案（承 Vol.4，本卷编号 1–17）

| # | 坑 | 根因 / 处方 |
|---|---|---|
| 1 | `animation-timeline: view()` 追错对象 | `body { overflow-x: hidden }` 被 CSS 规范强制把 `overflow-y` 变为 `auto`，body 成了滚动容器。改用 `overflow-x: clip` |
| 2 | 元素宽于父容器时不居中 | Chrome 对 `margin-inline: auto` 不平分（左边距钉死 0，溢出量全塞右边）。改显式 `margin-left/right: calc(...)` |
| 3 | 放大需要预留一块空白 | `transform: scale` 不改变布局盒子。改**布局宽度动画**，页面自然回流把下方内容推开 |
| 4 | 滚动动画生硬、无惯性 | CSS `view()` 严格绑定滚动位置、零惯性。要 scrub 感须用 rAF + 指数平滑 `cur += (eased - cur) * 0.08` |
| 5 | 动画终点算错、上下不对称 | 终点必须用**末态几何**（放大后高度、margin 归零后位置）计算，不能用初始几何 |
| 6 | 刷新后 LOGO / hero 位置错乱 | 标题字体从兜底 Times 换成 Instrument Serif 时页头高度跳约 84px。一次性判定必须等 `fonts.ready`，且重算后要重置相关状态 |
| 7 | 内联 SVG 里的 mono 字体不生效 | `next/font/local` 注册的是哈希名（`__geistMono_xxx`），只通过 CSS 变量暴露，字面量 `"Geist Mono"` 匹配不上。需额外写字面量别名 `@font-face` 指向同一文件（同 URL，不增加请求） |
| 8 | `<img>` 引入的 SVG 用不上站内字体 | `<img>` 加载的 SVG 是独立文档，够不着宿主页面的 `@font-face`。需 **inline** SVG |
| 9 | `::selection` 整条失效 | `::selection` 与 `::-moz-selection` **不能写在同一条逗号选择器里**，Chrome 认不出后者会丢弃整条规则。拆成两条 |
| 10 | MDX 里图注被正文样式接管 | 图注写成 JSX children 会被 remark 自动包一层 `<p>`，被 `.prose-works p` 命中。**用字符串 prop 传入**，不用 children |
| 11 | 每页图片停驻位置不同 | 滚轮落点量子化 + 各页页头高度不同。**统一页头最小高度**可让全站行为一致 |
| 12 | 大步长滚动跳过中间动画态 | 中间态若只靠滚动位置驱动，一步跨过窗口就永不渲染。改**阶段状态机 + 最小停留时长**，键盘 PageDown / 锚点跳转同受益 |
| 13 | Tailwind 类名用模板字符串拼接静默失效 | 静态扫描器看不到动态拼出的 class 名。**必须写字面量静态字符串** |
| 14 | Notion 导出的 `.csv` 可能实际是 Excel 二进制（zip） | 读前先验格式；用 `openpyxl` 转成真正的纯文本 CSV |
| 15 | `subset-fonts.mjs` 只扫 `content/`/`app/` 的 `.mdx/.tsx/.ts` | **数据文件（CSV）里的中文从未进过字体子集**。已把 `design-refs/*.csv` 纳入扫描；任何新增数据源都要确认在扫描范围内 |
| 16 | 同一组件叠了两套分隔线实现（`box-shadow` + `background-image`） | 半透明线叠加会变深。一处只留一套实现 |
| 17 | CSV 的 Windows 换行 `\r` 残留 | `split('\n')` 后末列名带 `\r`，匹配失败导致整列空白。读取时统一处理 |

## 附 B · 已撤销 / 已否决的决策（防止未来重新引入）

| 决策 | 否决理由 |
|---|---|
| **hero 吸附（snap-to-center）** | 与字体加载存在竞态，会用错误的 endScrollY"很自信地"锁死位置；且 Anthropic 自己也不吸附 |
| **`text-wrap: balance` 用于图注** | 段落该用 pretty；balance 让每行右边都空一截，整块变窄 |
| **信息海报体裁的 hero** | 剧透正文、手机上小字变蚂蚁、PS 重排文字成本极高 |
| **hero 比例 3:1** | 主体从 1538 缩到 1128px，"清明上河图"感 |
| **HERO_BAND = 90** | 主体瘦 5%，卷轴感回归；退回 71 |
| **hero `sizes = 150vw`** | +293% 字节；根因是档位阶梯粗（2048→3840），改 130vw + 新增 2560 档 |
| **白卡裱图（截图外包白卡 + 20px 内衬）** | A/B 对照后作者选细边版 |
| **代码块引入语法高亮库** | 整套主题带进 5–8 种颜色，违反色彩纪律 |
| **双表用 terracotta 强调 P0 / Missing** | 强调错了轴（该图论证结构非紧急度）；表 B 全 P0 无区分度；四处陶土爆预算 |
| **机制图中的「结构化输出」节点** | Schema 框本身就是结构化输出，另立节点是重复；且导致弯箭头 |
| **人工审核框内容居中** | 是拿对称掩盖留白的省事做法；框缩窄后改回左对齐 |
| **"4 个真实场景" / "真实的 messy input"** | input 实为模拟；overclaim 会让可核验的部分也被怀疑 |
| **图注双语改单语** | 已决之案：图注是文字逻辑非图名逻辑，左对齐 + 故意写长，双语是为了撑长度避免重心偏坠 |
| **重写 git 历史清除未打码截图** | 泄露内容为平台名 + 本机用户名，无密钥无隐私；force push 代价大于收益 |
